# AI 创意画布（ai-creative-canvas）

> 无限自由画布上的 AI 影像创作 + 媒体编辑工坊。在一张可无限平移缩放的画布上，以「卡片」为单位**逐张**生成图像 / 文本 / 视频 / 配音，并内置一套**逐卡片媒体后期工具箱**（裁剪 · 扩图 · 抠像 · 放大 · 宫格分镜 · 视频裁剪 · 转 GIF · 抽帧 · 镜头检测 · 音视频分离 · 倒放 · 压制）。

画布引擎**完全自研**（DOM 卡片 + 单一 CSS transform 世界层 + SVG 连线 + 自写图状态，参考 AI-CanvasPro 的实现路线），不依赖任何第三方画布库。

## 与 ai-film-studio 的区别

| | ai-film-studio | **ai-creative-canvas（本插件）** |
|---|---|---|
| 范式 | 故事→分镜→成片的**自动流水线**（一键 Run All） | **自由画布 + 逐卡片按需生成 + 富媒体后期编辑** |
| 画布 | React Flow 流程图 | 自研无限白板（自由摆放/缩放/连线/多画布） |
| 重心 | 编排自动化 | 创作探索 + 媒体编辑工具箱 |

两者定位互补，互不冲突（独立的 id、触发词、存储与落盘目录）。

## 触发方式

在 Mulby 搜索框输入以下任一关键词：

- `创意画布` · `无限画布` · `AI画布`

或把图片 / 视频 / 音频 / 文本文件拖到 Mulby（`img` / `files` 触发），会直接在画布中创建对应卡片。

## 功能

- **无限画布**：滚轮缩放（朝光标）、空格 / 中键拖拽平移、框选多选、拖动、网格、小地图、适配视图、撤销/重做、多画布 Tab。
- **卡片**：文本 / 图片 / 视频 / 音频 / 素材 / 便签 / 分组。可用左侧「导入」、系统拖拽、剪贴板粘贴或 Mulby `img/files` 触发引入资源；图片、视频、音频和文本会自动落为对应类型。素材卡是不会被 AI 重新生成覆盖的独立资源节点，用于承载本地导入文件或固定从生成卡拖出的某次结果，供下游节点引用；为避免与「导入」重复，不再提供单独新建空素材卡的入口，已有空素材卡仍可选择文件继续使用。
- **节点编辑**：单选节点时使用加宽的紧凑面板编辑名称、提示词、模型、参数和引用素材；“输入预览”和“上次生成”诊断按需展开，媒体后期工具保持在卡片外独立悬浮。“润色”只修改当前提示词输入框；视频卡的“导演增强”则会读取真实上游文本、选中的参考图、参考视频标签、风格包、镜头参数和 Provider 能力，先生成可预览的导演方案；点击“应用到本次生成”后返回视频卡，再点击“使用导演方案生成”。视频参考区显示自动推断模式、Provider 数量上限和有序素材列表，可上移 / 下移引用，并可直接添加公开 `http(s)` 视频 URL。素材节点显示用途、类型、大小、本地定位与明确的选择 / 更换文件入口；主资源缺失时可直接重新关联。文本节点明确区分「生成指令」与可手填、可修订并供下游消费的「文本内容」；便签双击后直接原位编辑。提示词、参数、模型及素材变更均按编辑事务进入撤销历史。
- **标注层**：在画布上用画笔 / 形状 / 文字批注（随工程持久化），供审阅与讲解。
- **对齐分布**：拖动时吸附对齐参考线；右键菜单对齐 / 分布多张卡片。
- **AI 生成**（Mulby 原生）：
  - 文本卡：`ai.call` 流式生成（分镜脚本 / 文案 / 提示词扩写），支持看图（引用图片作 vision 输入）。
  - 图片卡：`ai.images` 文生图（流式进度 + 预览）、图生图、多图参考一致性（`referenceAttachmentIds`）。模型选择器同时显示 Provider，生成后记录实际发送文本、Provider、请求 / 任务 ID，可在节点内复制诊断信息排查第三方服务串图。
  - 视频导演增强：按当前 Provider 能力读取实际选中的有序参考图作为视觉输入，并把参考视频的标签和 URL 语义纳入规划；结构化规划可见动作、未解状态、主体锁定、空间关系、构图视觉流、时间弧线、主体 / 环境 / 摄像机运动、实景光源、色彩命题、镜头约束与原生音频。方案经本地编译为最终提示词，保留显式 `@`引用语义；内容、素材、顺序、风格、参数或 Provider 变化后方案会标记过期。应用到当前视频卡的导演方案仅消费一次，生成成功后清除；即使任务中断后恢复，也会记录实际发送内容与“导演增强”标记。
- **引用**：把一张卡片连线到另一张（拖卡片右侧圆点），或在节点编辑器用 `@` 选素材 / `/` 选预设。文本 / 图片 / 全景节点接收文本和图片，音频只接收文本；视频节点可保留文本、图片和视频引用，再由当前 Provider 能力决定可提交的数量、参考模式与是否允许图 / 视频混合。普通旧 Provider 仍只消费 1 张通用参考图，首尾帧模式消费 2 张；支持多模态的 Provider 可声明更高上限。超量、不支持的混合输入和仅本地可用的视频会在付费提交前明确拦截，不会静默丢弃。未写 `@` 时，全部上游有效素材自动成为输入；写了有效 `@名称` 时只使用被点名的素材，文本会原位展开，图片与视频保持附件语义。编辑器可按需展开实际内容输入；无效或空引用会明确提示。
- **语义素材与 AutoLink**：图片、全景、文本、音频和素材节点可登记为工程内的角色、场景、道具、声音、风格、音乐或参考锚点，并设置名称、别名、描述与标签。锚点可跟随源卡最新产物，也可锁定当前产物；锁定后即使源卡重新生成或删除，引用仍保持可用。提示词会根据名称、别名、标签和语境显示本地引用建议，只有用户点击“引用”后才建立稳定 `anchorId` 绑定；接受建议不会自动排除其他上游素材，只有显式写出 `@锚点名称` 才会缩小本次生成输入。锚点改名会同步展示名称和已有 `@` token。
- **图像媒体工具箱**（`sharp` + `ai.images.edit`）：裁剪（框选）、扩图、放大、抠像/去背景、宫格分镜切分（2×2 / 3×3 / 1×3）。
- **统一版本工作区**：图片、视频与导演台 Take 使用同一套版本读取模型；卡片悬浮媒体工具可打开接触表，选择 A/B 放大比较、标星、淘汰、采用为当前版本，并可把任意版本另起为可继续生成或编辑的画布分支。旧图片 `meta.results` 与导演 `takes` 无需手工迁移即可读取；新生成结果会写入统一版本状态并保留实际提示词、模型与 Provider 追踪信息。
- **视频媒体工具箱与视觉拉片**（`ffmpeg` + Mulby Vision，FFmpeg 首次自动下载）：除裁剪片段、转 GIF、抽帧、镜头检测、提取/去除音轨、倒放和压制外，视频卡还可打开近全屏“视觉拉片”工作台。系统按场景切分镜头，为每镜抽取首 / 中 / 尾帧并分批分析场景、景别、构图、人物、动作、可验证的镜头变化、光色与情绪；结论可逐项修订、可更换代表帧，并可幂等落地图片卡或转换为带源视频时间范围的故事板。连接带时间码的 SRT / VTT 文本时会按镜头合并对白；没有字幕时明确显示“未转写”，不会猜台词。报告和抽帧会随便携工程一起迁移。
- **视频局部重拍**：剪辑工作台可在当前播放头附近选择单个问题区间，自动抽取首帧、代表帧与尾帧，继承原镜头提示词、故事板关联、语义锚点、风格包和导演增强上下文。替换片段根据 Provider 能力使用首尾帧或参考图生成，完成后通过 `replace` 编辑层自动拼回新视频卡；原视频、替换片段和可二次编辑的配方都保留，插件中途退出后可继续自动回填。
- **局部重绘**（蒙版 inpaint）：双击图片卡进入大尺寸局部编辑工作台，可滚轮缩放、手型工具平移和一键适配视图；既可涂抹精确蒙版，也可直接在图片上画红色箭头、添加黄色文字说明修改位置与要求。标注会随参考图发送给模型并注入“理解后移除标记”的约束，结果通过 `ai.images.edit` 非破坏式生成到新卡片。
- **分镜工作台**：顶栏可在“画布 / 故事板”双视图间切换；故事板工作区按工程汇总镜头，左侧用角色、场景、道具等语义锚点筛选，中部提供列表 / 缩略图密度和状态筛选，右侧镜头检查器编辑画面、图片 / 视频提示词、对白、音效、时长与关键元素。镜头使用稳定 ID 并与画布产物双向关联，可查看未落地、待生成、输入已变、生成中、失败和已完成状态，幂等同步、生成缺失产物、创建 / 打开视频卡并双向定位。自动排版只移动当前故事板关联产物且只占一个撤销步骤；50 镜以上启用虚拟滚动，删除镜头会保留产物为自由卡片。
- **创作 Agent（多 Canvas Recipe）**：顶栏机器人入口打开可并行使用的 Agent 抽屉，现提供“剧本转短片”和“产品广告短片”两种受控配方。机器人图标上的数字只表示当前工程中待确认、执行中、失败或已失效的待处理工作流数量；抽屉标题栏的“历史”入口可查看全部记录、切换回任意计划、逐条删除，或批量清理已完成 / 已取消 / 已失效记录，删除记录不会删除画布产物。后者会从产品 Brief、相连素材、语义锚点和风格中提炼核心主张、可验证卖点、品牌强制元素与 CTA，再生成广告镜头。两种配方都使用各自的严格 JSON Schema；模型不直接操作画布，实际执行被限制为“保存故事板、准备 / 生成 / 锁定连续性设定、落地 / 生成静帧、创建 / 生成视频、送入时间线”九个本地白名单动作。工作流不会再让每个镜头各自猜测人物和道具：它会优先复用相连图片与已有视觉锚点，为缺失的角色、场景、产品和关键道具生成 1:1 设定图，等待人工确认并锁定当前媒体快照，再把同一批锚点注入所有相关镜头。画幅会贯穿静帧、视频卡和最终时间线；“目标总时长”表示最终成片长度，插件会把它分配给各镜头。若 Provider 只能生成更长的固定档位，视频卡保留完整原始素材，时间线按镜头计划自动预裁切，费用仍按真实生成量估算。任务规模、连续性设定图数量、Provider 能力冲突和费用可知性在执行前展示；创作规格、视觉设定与静帧是三个显式检查点。步骤、日志和产物卡 ID 随工程保存，支持暂停、重开恢复、取消、错误重试和幂等重跑。可手动选择 Mulby 已启用 Skill；Agent 调用固定关闭 MCP 与内部工具，Skill 只用于策划知识增强。
- **3D 导演台**：three.js 3D 场景摆位、运镜预览与「机位即分镜」工作流；内置 13 套 CC0 独立人物网格（成年男女、少年少女、男童女童、幼儿、老年男女及宽厚 / 健壮 / 纤细 / 丰腴体态）和 20 种姿势。人物资源按工程所需与首次选择加载并在会话内缓存；姿势库会按当前体型生成真实缩略图，支持关节 XYZ 微调、活动范围校验，以及按住 Shift 拖动手腕 / 脚踝进行轻量 IK。控制面板按对象 / 角色 / 镜头分区，支持可调宽侧栏、隐藏滚动条的滚轮与触控滚动、8 个跟随人物朝向或覆盖全场景的语义机位、30% / 50% / 70% 主体占画面推拉、导演视角 / 机位视角切换、冻结机位 PiP、灯光预设，以及可排序的底部机位分镜条。机位可绑定任意场景对象并在对象移动后保持原构图跟随；新机位默认保存人物和道具的走位、朝向、体型、姿势与显隐，切换时可恢复完整镜头，也可只应用相机。连续性检查覆盖跳切、机位反转、焦段 / 画幅 / 灯光突变，以及演员走位、朝向、姿势和入离场变化。镜头面板支持导入 JPG / PNG / WebP 等距柱状全景背景，也可直接选择当前画布已完成的 360 AI 全景；背景会复制为导演工程独立附件。全景可选择 GroundedSkybox 落地环境或无限背景，使用 PMREM 为人物和道具提供环境光，并以 ACES 曝光、地平线、拍摄高度、背景柔化及透明接影面完成校准。环境可保持与主体共用镜头的物理一致模式，也可切换构图适配模式，通过独立环境相机调整背景视觉尺寸而不缩放人物。导演台会保存全景拍摄原点，实时显示相机偏移和视差风险，可一键回到拍摄点；新机位还会保存背景构图模式和尺寸，并在分镜条标记近似透视镜头。环境描述仍会进入生成提示词。顶栏可导入导出便携导演工程 JSON，模型和全景附件会一并打包。另支持逐机位画幅 / 灯光快照、take 历史、批量生成和一键导出分镜到画布。
  - 生成链路是 img2img 软参考（`images.edit` 无强度/控制通道），构图跟随度很大程度取决于模型本身：实测建议优先选构图保持强的编辑模型（如 `google:gemini-2.5-flash-image`），同场景与 gpt-image 系各出 2 张对比后再定默认图像模型。
  - 技巧：镜头区「画幅」选定后抓帧按此裁剪（框内即模型所见）；给人台填「描述」（如"穿长衫的老者"）会按方位自动装配进提示词；要硬约束（严格按深度/骨架构图）需把工程设置的「ControlNet 控制模型」指向真 ControlNet 端点。
  - 视角语义：`机位视角`直接编辑最终出图相机；切到`导演视角`会冻结当前机位，可自由绕场检查摆位，并通过右上角 PiP 监看最终画面；“更新机位”会把当前导演观察角度写回出图机位。
  - 年龄、性别和体态差异已固化为独立网格，运行时不会拉宽、压扁或放大头部来伪造体型；模型加载异常时才回退到程序化人台。体型、姿势和手动关节调整均随工程保存，资产声明见 `THIRD_PARTY_NOTICES.md`。
  - 女性素体采用弱化生理细节的中性胸廓和低对比人台材质；性别与体态主要由脸型、肩胯比例和整体轮廓表达，以降低参考图触发 NSFW 过滤的概率。
- **360 全景**：独立全景卡片类型（文/图生成 2:1 等距柱状）+ 节点内拖动环视预览（可截取视角为新图片卡）+ 接缝/天地修复。
- **可插拔视频/音频生成**（外部 Provider，右上角「设置」配置）：
  - 视频：通用「异步 submit + poll」，按 JSON 路径映射任务 id / 状态 / 结果 URL（兼容 fal、Replicate 风格），支持图生视频。
  - 内置 `Raydu · Seedance 2.5` 异步 / 同步直连模板：异步版映射任务提交和轮询，兼容嵌套 `result.videoUrl / ossUrl / originalUrl / videoUrls[0]` 及旧版顶层结果字段；提交后按 5、10、15、20、30 秒退避查询，后续每 30 秒一次，优先遵循响应头 `Retry-After`，最长等待 40 分钟。同步版单次等待结果，客户端超时为 720 秒、服务端等待上限为 600 秒，并按 `videoUrl → ossUrl → originalUrl` 回退取结果。两者均关闭提交自动重试以避免重复创建计费任务，支持文生视频、1–9 张参考图、1–3 条公开参考视频 URL、图 / 视频混合参考、720p/1080p、五种画幅、5–30 秒及原生音频；素材数量交给服务端自动推断 `text2video` / `singleImage2video` / `frames2video` / `image2video` / `mixed2video`。
  - 音频：OpenAI 兼容 `/audio/speech` 配音。
  - 设置按「基础 / 高级 / 诊断」分层：基础页声明文生视频、图生视频、尾帧、原生音频、参考图 / 视频上限、图片传输方式、混合引用及画幅 / 时长 / 分辨率能力。高级请求模板保留 `{imageUrl}` / `{lastImageUrl}` 兼容占位，并提供安全 JSON 数组占位 `{$images}` / `{$videos}`；视频卡片会据此收窄参数并在发起请求前拦截不支持的输入。
  - 高级页可选填写每次请求 / 每秒费用、币种和确认阈值；批量生成与 Agent 会据此估算。未配置单价时明确显示“费用未知”，不会伪造报价。
  - 诊断页提供配置校验、密钥与敏感请求头脱敏的请求预览，以及不创建计费任务的分级连通测试；通用自定义接口无法验证鉴权时会明确标为“部分通过”，不再把首页 404 当成完整成功。
  - API Key 经系统安全存储加密保存；Provider 导出不包含密钥，导入会校验基础结构且需要重新填写密钥。
- **工程库 / 任务中心 / 作品库**：多工程管理与切换；生成任务队列、Agent 工作流、检查点与失败状态总览；已完成媒体画廊浏览并可定位回画布或 Agent。
- **模板**：内置工作流模板（文生图链 / 图生视频链 / 分镜扇出），一键铺入画布。
- **持久化**：工程（画布/卡片/连线/视口）自动保存到 Mulby storage；媒体文件落本地磁盘（`<userData>/ai-creative-canvas/media/<projectId>/`）。工程的“含媒体导出”会按物理文件去重，完整打包主产物、节点内上传素材、多结果历史、剪辑配方资源、导演台 take 及模型 / 全景附件；导入时统一改写为新工程路径，并兼容旧版媒体信封。工程库的“清理未引用媒体”会综合全部工程、恢复快照、撤销历史和剪贴板后再回收文件，复制工程之间的共享引用不会被破坏。
- **导出**：选中带媒体的卡片，在节点编辑框点下载图标导出到任意路径；工程库可选择轻量 JSON（同机）或含媒体包（跨机）。

## 文本卡片与连线语义

- 文本卡片是可复用的**内容节点**：上方「生成指令」只负责告诉文本模型怎么写；下方「文本内容」才是它的产物，可由 AI 生成，也可直接手动填写。
- 文本卡片连到图片、360 全景或视频卡片后，它的「文本内容」自动成为下游主描述；下游输入框改作本节点的补充要求，因此可以留空。
- 下游同时有上游文本和本地输入时，实际内容按“上游文本 → 本节点补充要求”组合，并在编辑器中实时预览。
- `@文本卡片` 用于从多个上游素材中显式点名，发送前会展开成该卡当前的「文本内容」，不会把 `@卡片名` 原样发给模型。
- 文本卡片内容为空时不算有效输入；应先生成或手动填写内容。修改上游后，下游不会自动重跑，仍由用户决定何时重新生成。

## 剪辑 vs 时间线

- **画布时间线**（多卡片串片）：编排顺序、转场、混音，适合快速拼成片。
- **剪辑工作台**（单卡精修）：调色、字幕、PiP、特效等非破坏编辑栈，可二次打开继续改。
- **局部重拍**（单区间修复）：工作台顶栏“局部重拍”创建替换片段，生成完成后输出一张新成片卡，不覆盖原视频。

## 前置条件

1. **AI 模型**：在 Mulby「AI 设置 → 模型管理」配置：
   - 至少一个文本模型（文本卡）。
   - 至少一个 **image-generation** 端点类型的图像模型（图片卡 / 扩图 / 放大 / 抠像）。图片卡的模型选择器会自动选中第一个可用图像模型。
2. **FFmpeg**：视频工具首次使用时会自动下载 FFmpeg（带进度提示），无需手动安装。
3. **视频/音频生成 Provider（可选）**：右上角齿轮「设置」选择模板或新建 Provider，在基础页配置端点、模型、能力与 API Key；保存前建议到诊断页确认请求预览并执行安全测试。不配置也不影响核心功能（文/图生图、全部媒体编辑、文本均为 Mulby 原生、零外部密钥）。

## 技术栈

- 前端：React 18 + 自研画布引擎 + zustand（状态）+ Tailwind（面板样式），Vite 构建。
- 后端（host-worker，`src/main.ts`）：承担渲染进程不便/易截断的工作 —— 系统拖拽文件读取与受管目录复制、远程媒体落盘（规避 CORS）、图床 multipart 上传、OpenAI 兼容 TTS 二进制合成、导出落盘。
- Mulby Host API：`ai`（文本/图像/附件）、`sharp`、`ffmpeg`、`http`、`storage`（含 encrypted）、`filesystem`、`system`、`notification`、`theme`、`host`。

## 开发

以下命令**不依赖 Mulby CLI**，克隆后开箱可跑：

```bash
pnpm install       # 安装依赖（pnpm workspace）
npm run typecheck  # 三段 tsc：src / node 配置 / test（test 见 tsconfig.test.json）
npm test           # 编译快照 + store + engine 单测
npm run build      # typecheck → esbuild 后端 → vite UI
```

`dev` / `pack` 需要 **Mulby CLI**（`mulby dev` 热载调试、`mulby pack` 打包 `.inplugin`）。CLI 在同一 workspace 的 `mulby/packages/mulby-cli`，先在该目录构建并全局链接（或把其 bin 加入 PATH）使 `mulby` 命令可用，然后：

```bash
npm run dev   # = mulby dev
npm run pack  # = npm run build && mulby pack
```

## 已知限制

- Mulby 内置 AI 无视频生成、TTS 仅即时播放（不产文件），故**视频生成与配音文件依赖外部 Provider**（已做成可插拔）。
- 为控制 host-worker 内存峰值，远程生成媒体单文件下载上限为 **256MB**，图生视频的图床上传单图上限为 **50MB**。
- 单次本地导入最多 **64** 个文件；文本文件上限为 **5MB**。本地媒体采用后端直接复制，不经前端 Base64 膨胀。
- 媒体清理对创建不足 5 分钟的文件设置保护期，防止仍在落盘的生成或编辑任务被误删；这些文件可稍后再次清理。
- 画布能保证并记录实际发给宿主的提示词，但无法仅凭返回像素可靠判断第三方图像 Provider 是否忽略提示词或串回了其他任务；遇到完全无关的结果时，应凭节点记录的任务 ID 排查服务端，并切换到其他 Provider 复测。
- 镜头检测输出的是每个切点的代表帧（用于快速搭分镜），不直接产出按时间切好的片段。
- 360 全景是独立 pano 卡（v2 迁移自图片卡开关）；渐进式 outpaint 已废弃，见 `docs/360-current-route.md`。
- 单张 360 全景没有真实深度。导演台的落地环境适合固定机位、旋转镜头和小范围移机；大幅推拉、横移或绕拍仍应使用真实 3D 场景、深度代理或其他空间重建资产。
