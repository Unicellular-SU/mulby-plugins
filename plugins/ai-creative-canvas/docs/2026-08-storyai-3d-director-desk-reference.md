# storyai-3d-director-desk 参考分析

## 参考范围

- 上游项目：<https://github.com/jiguang132/storyai-3d-director-desk>
- 研读提交：`8c8bd361790be4d37158a7430365e65546e358fe`（2026-07-06）
- 上游许可证：MIT
- 重点文件：顶层壳布局、对象树、右侧检查器、视口工具栏、导演状态模型、机位几何、截图与 README 截图。

本次只吸收产品结构和交互思想，没有复制上游源码、样式表、模型或图片资产。上游内置 UE Mannequin 另带 Sketchfab Standard 许可，因此没有引入本插件。后续人物升级改用 MakeHuman 官方 CC0 核心资产生成 13 套独立网格，许可链与上游模型无关。

## 结论

参考项目在“传统 3D 编辑器的可理解性”上做得很好，尤其是三栏工作区、导演 / 机位视角分离、可搜索对象树、对象锁定和数值检查器。AI 创意画布原有导演台则在后续创作链路上更完整：场景语义自动装配提示词、深度 / OpenPose 控制图、机位 take 历史、批量生成以及导出分镜卡。

合理方向不是替换现有实现，而是把参考项目清晰的 DCC 信息架构接到现有 AI 生成闭环上。

## 已采用

| 参考点 | 本插件实现 | 价值 |
|---|---|---|
| 导演视角 / 机位视角分离 | 顶栏增加明确的双模式切换。机位视角直接编辑出图相机；导演视角冻结出图机位，主视口可自由绕场，PiP 持续监看最终构图 | 消除原“锁定取景”开关的语义成本，降低误把观察角度写成最终机位的风险 |
| 全屏视口与可收起面板 | 增加专注取景按钮，左右侧栏收起后构图线、画幅框、PiP 和底部提示词区自动扩展 | 在插件最小窗口和复杂场景中获得更大的可用取景面积 |
| 对象树搜索与类型分组 | 左侧按人台 / 道具 / 模型分组，支持名称与类型搜索，并显示过滤计数 | 大场景中更快定位对象，减少平铺列表扫描 |
| 对象显隐与锁定 | 对象行增加显隐、锁定、复制、删除；锁定后仍可选择和查看，但禁止 gizmo、摆姿与数值变换 | 防止镜头微调时误碰已经定好的主体 |
| XYZ 数值检查器 | 右侧增加位置、旋转（角度制）、缩放三轴输入，与 TransformControls 双向同步 | 支持可复现的精确摆位，而不只依赖鼠标拖拽 |
| 编辑状态持久化 | 对象的 `visible` / `locked` 与变换一起进入场景快照和撤销栈 | 关闭重开、撤销重做后仍保持工作现场 |
| 多机位空间可视化 | 已记录机位进入 Outliner；导演视角可同时显示全部相机取景框，并以琥珀色区分当前机位 | 在场景空间中直接比较不同镜头的位置、方向和焦段，不必逐个切换猜测 |
| 镜头计划与连续性 | 每个机位可编辑时长和导演备注；分镜条显示总时长，并检查跳切、方向反转、焦段 / 画幅 / 灯光突变 | 让机位序列具备基础剪辑节奏和连续性反馈，而不只是一组静态截图 |
| 目标绑定与跟随 | 机位可绑定场景对象，以相机和目标点相对对象原点的偏移保存；应用机位、辅助框、连续性检查和分镜导出统一解析当前构图 | 人物或产品改位后不必逐镜重设相机，并避免不同出口看到不一致的机位 |
| 全景环境 | 可导入 JPG / PNG / WebP 等距柱状全景背景，调整水平旋转，并把环境描述写入生成提示词 | 让场景空间、预览背景与 AI 环境语义保持一致 |
| 便携导演工程 | 导入导出带版本标识的 JSON；GLB / GLTF 与全景附件使用 Base64 一并打包，导入时校验尺寸、重映射附件 ID 并确认替换 | 在 Mulby storage 之外提供可备份、可迁移的交换格式，同时兼容旧版裸场景 JSON |
| 逐镜头演员调度 | 新机位记录对象走位、朝向、体型、姿势与显隐；应用时可恢复完整镜头或只切换相机，更新时也可分别覆盖 | 同一场景的不同镜头可以保留独立表演和走位，旧机位继续按仅相机模式兼容 |
| 演员连续性 | 相邻镜头检查对象位移、朝向突变、姿势变化和入离场，并与原有相机连续性提醒合并展示 | 在生成前暴露常见的动作衔接和空间跳变问题 |
| 画布全景复用 | 环境面板列出当前画布已完成的 360 AI 全景，读取完整媒体后复制为导演工程附件，并继承全景提示词 | AI 全景无需先手工下载再导入，源卡删除也不会破坏导演工程背景 |
| 全景环境融合 | 落地模式使用 GroundedSkybox 投影下半球，PMREM 为 PBR 材质提供环境光，透明接影面替代灰色实体地板；无限背景模式保持背景位于相机远处 | 减少人物像贴在背景照片前的割裂感，并让脚底、反射、曝光和场景方向可以统一校准 |
| 环境校准 | 保存拍摄高度、地平线、曝光、环境光强度、背景柔化和接影强度；导入后显示真实像素尺寸与质量等级 | 让本地全景和画布 AI 全景经过同一套可复现的摄影参数进入场景 |
| 环境构图分层 | 全景背景使用独立环境相机先渲染，清除深度后再合成人物、道具和接影；物理一致模式共用视野，构图适配模式可在 50% 到 200% 范围调整背景尺寸 | 解决全景视觉尺度过大时只能拉远整台相机、导致人物同时变小的问题，并让主视口、PiP、缩略图和参考图保持一致 |
| 主体占画面 | 提供 30% / 50% / 70% 三档快捷构图，优先使用所选对象，否则覆盖全部可见对象；仅沿视线推拉相机 | 在不缩放人物、不改变焦段的前提下快速恢复主体尺寸，适配横竖画幅裁剪 |

## 保留现状或暂不采用

- 不迁移到 React Three Fiber / drei。现有原生 Three.js 运行时已稳定，且支持动态分包、深度图、OpenPose、双渲染器 PiP 和宿主附件持久化；为 UI 结构改造更换渲染架构收益不足。
- 不引入上游 UE Mannequin GLB。人物资产改用许可明确的 MakeHuman CC0 核心网格和统一 humanoid 骨架；程序化人台只作为加载失败时的回退。
- 暂不加入 FBX / OBJ 和模型库弹窗。Mulby 插件当前以 GLB / 内嵌 GLTF 为可持久化最小路径；FBX / OBJ 的贴图依赖、资源打包和跨会话恢复需要单独设计。
- 暂不加入大规模群众阵列。它值得作为后续能力，但必须先解决实例化渲染、角色语义编号、颜色锚定复用和 OpenPose 输出密度问题，不能只做批量 clone。
- 不照搬纯黑 + 蓝色高亮主题。现有暖黑 + 琥珀色“摄影监视器”视觉与 AI 创意画布整体风格一致，仅借鉴信息层级、面板密度与模式切换形式。
